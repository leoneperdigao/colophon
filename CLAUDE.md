# CLAUDE.md — Document Annotation Service

Event-driven document annotation service: `POST /documents` returns a job ID
immediately, a background worker runs the document through **raw → curated →
annotated** stages with an LLM, and `GET /annotations/{job_id}` returns the
result. This is an **8-hour take-home** — a clean, runnable, well-tested slice
plus a README that reasons about the rest. **Restraint is graded.**

## Locked stack (no substitutions without asking)

Python 3.12 · FastAPI · pytest · docker-compose (api + worker + rabbitmq + minio
+ postgres). **RabbitMQ** behind `Messaging` (queue = work, topic exchange =
events, DLX = dead-letter) · **MinIO** behind `BlobStore` · **Postgres** behind
`AnnotationStore` · **LiteLLM → Anthropic** behind `LLMClient` (tool-use for
strict JSON, Haiku-tier model; model id + key in env, never in code).

## Architecture rules

- **Hexagonal, light.** Domain + application depend only on ports. Ports exist
  only where a real second implementation does: `BlobStore`, `Messaging`,
  `AnnotationStore`, `DocumentParser`, `LLMClient`. No layering for its own sake.
- **Vertical slices, not horizontal layers.** First slice end-to-end and
  running: upload → 202 + job_id → enqueue → **stub worker** that just advances
  stages → fetch by id, with auth + tenant threaded. Get that green before any
  real parsing or LLM. Then thicken in place.
- **Stay runnable at every slice.** If an infra adapter fights the environment,
  fall back to the in-memory fake behind the same port, keep the system running,
  and note the gap. Do not let a wedged subagent burn the clock — surface it.
- **Single bounded annotation agent**: classify → type-specific structured
  extraction (Anthropic tool-use) → validate/repair. **No autonomy, no
  multi-agent orchestration, no tools with side effects.**

## Non-negotiables

- **Test-first (TDD).** Port tests against fakes first (red) → implement (green)
  → refactor. **The domain and application layers must be fully testable with no
  infra running.** Quality is measured by the gold-set eval with thresholds
  (`make eval`), not by inspection.
- **Tenancy is an access boundary.** `tenant_id` is derived from the Bearer
  credential, **never client-supplied**. Thread it through domain, storage keys,
  store rows, message metadata, and logs. Every read/write is tenant-scoped;
  another tenant's job id returns **404**, not the record.
- **Idempotency:** `job_id = hash(tenant + content + filename)`; forward-only
  stage transitions.
- **Security by default.** Secrets never in the repo (`.env.example` committed,
  real `.env` gitignored, keys only in the LLM gateway). Per-component
  least-privilege creds. All uploaded content is untrusted: size/content-type
  validation, parse timeouts + page/sheet caps, spreadsheet **values not
  formulas**. Non-root containers.
- **Subagents parallelize ONLY along ports** (parsing, llm, blob, store adapters
  are independent given fixed port interfaces — one subagent each is safe). Keep
  the **domain core and composition root sequential and coherent** — never
  parallelize those.

## OUT OF SCOPE — do NOT implement (document in README only)

This list **overrides** the Superpowers "if a skill might apply, use it" bias.
If you think one of these is needed, **stop and ask** rather than building it:

- Postgres row-level security (build only if everything else is done early)
- EventBridge / Step Functions / topic-exchange stage events as separate infra
  (single worker runs the stages in-process; document the split)
- LiteLLM **proxy** container (use the SDK)
- CDK serverless stack and k8s manifests (sketch in README / `infra/` only)
- OpenTelemetry tracing
- Full identity / IdP / OAuth (the thin token→tenant map is the whole auth build)
- Full multi-tenant isolation, silo deployment, per-tenant KMS
- Malware scanning, WAF, rate limiting
- LLM-as-judge; online / drift eval (the deterministic gold-set + groundedness
  checks ARE built; the judge and monitoring are documented only)

## Branching strategy

Trunk-based, aligned with how Spec Kit and Superpowers already work. See
`docs/BRANCHING.md` for the full policy. Short version:

- **`main` is the protected trunk** — always green, always runnable. No direct
  pushes; everything lands via PR.
- **Spec Kit owns the feature branch.** `/speckit-specify` cuts
  `NNN-short-name` (e.g. `001-document-annotation`) off `main` and writes
  `specs/NNN-short-name/`. Commit the spec artifacts there; that branch is the
  integration line for this feature.
- **Implementation happens on short-lived slice branches** off the feature
  branch, one per vertical slice or per port adapter
  (`feat/<NNN>-<slice>`, e.g. `feat/001-parsing-adapter`). Superpowers may use
  **git worktrees** to run port-adapter subagents in parallel without conflict.
- **Conventional Commits** (`feat:`, `fix:`, `test:`, `chore:`, `docs:`).
  Keep commits small and green; never commit on red.
- **Squash-merge** slice branches up to the feature branch, then the feature
  branch to `main` via PR. Rebase on `main` rather than back-merging.
